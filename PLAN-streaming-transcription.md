# План: потоковая транскрибация аудио в Jarvis

## Цель

Сделать голосовой ввод с микрофона и прослушивание аудио из динамиков непрерывными: запись не ограничивается одним двухминутным файлом, а разбивается на последовательные чанки по 2 минуты. Каждый завершённый чанк транскрибируется в фоне, а результат **дописывается** в поле ввода, не затирая уже введённый вручную или распознанный текст.

## Уточнение от пользователя

При **повторных** ручных нажатиях кнопки (запуск → остановка → запуск → остановка) транскрибированный текст из нового прослушанного потока тоже должен **дописываться** к существующему тексту в поле ввода, а не заменять его.

## Объём изменений

### 1. **AgentService.qml**

- Добавить свойства:
  - `voiceChunkDuration` (фиксировано 120 сек)
  - `voiceCurrentChunkSeconds` (счётчик текущего чанка)
  - `voiceChunkQueue` (очередь чанков на транскрибацию: `[{path, index}]`)
  - `voiceChunkIndex` (порядковый номер чанка)
  - `voiceTranscribing` (флаг активной транскрибации)

- Изменить `startVoice()`:
  - Инициализировать счётчики и очередь
  - Запустить запись первого чанка (путь = `voiceWav + "-" + index`)

- Изменить `voiceTicker`:
  - Увеличивать `voiceCurrentChunkSeconds`
  - При достижении 120 секунд вызывать `_rotateChunk()`

- Добавить `_rotateChunk()`:
  - Завершить текущий процесс `pw-record` (SIGTERM)
  - Добавить путь чанка в очередь транскрибации
  - Запустить обработку очереди, если она не идёт
  - Увеличить `voiceChunkIndex` и обнулить `voiceCurrentChunkSeconds`
  - Запустить запись следующего чанка

- Изменить `stopVoice()`:
  - Завершить текущий процесс `pw-record`
  - Добавить последний чанк в очередь
  - Переключить `voiceState = "transcribing"`
  - Запустить обработку очереди

- Добавить `_processNextChunk()`:
  - Взять первый чанк из очереди
  - Запустить `voice.py transcribe <chunk-path>`
  - В коллбэке парсить JSON:
    - Если `result.text` — **сразу вызвать `voiceTextReady(text)`**
    - Удалить файл чанка
    - Рекурсивно вызвать `_processNextChunk()`
  - Если очередь пуста:
    - Если `voiceState === "transcribing"` → `voiceState = "idle"`
    - Иначе (запись продолжается) — просто выйти

- Параметризовать путь к WAV в `recRunner` Component:
  ```qml
  property string wavPath: root.voiceWav + "-" + root.voiceChunkIndex
  command: [..., wavPath]
  ```

### 5. **Проверка**

- Один короткий чанк (< 2 мин) → текст появляется сразу
- Несколько чанков (> 4 мин) → текст добавляется по мере готовности
- Ручная остановка внутри чанка → последний чанк обрабатывается
- Повторный запуск после остановки → новый текст **дописывается** к старому
- Оба источника (mic / output) → без разницы

## Границы реализации

- Размер чанка фиксирован (2 мин), без нового параметра настроек
- Последовательная очередь (один `voice.py` в момент времени)
- Перезапуск `pw-record` между чанками (простейший вариант)
- Пустой результат не добавляет лишние переносы (проверка `if (result.text)`)
- Коммит/push только после подтверждения пользователя
